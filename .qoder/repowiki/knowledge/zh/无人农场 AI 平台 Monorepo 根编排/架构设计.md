根目录作为 monorepo 编排层，通过三个层次把子模块串联起来：
- 包契约层（shared_packages）：@agri/config、contracts、db、mq、observability、plot-core、shared、testing 等 TypeScript 包由顶层 tsconfig.json 的 project references 统一声明依赖顺序，构建产物输出到各包 dist 目录。
- 应用服务层（apps/*）：gateway-service、auth-service、iot-service、plot-service 等 NestJS 微服务均依赖 @agri/* 包，通过 Docker Compose 启动 PostGIS/MinIO 后由 scripts/* 中的 Node 脚本按编号递增执行 SQL 迁移并冒烟验证连通性。
- 前端层（legacy_webapp）：独立的 Vue3 + Vite 工程，通过 pnpm-workspace.yaml 的 allowBuilds 白名单放行 esbuild/vue-demi 等原生依赖的安装脚本。
测试侧 vitest.config.ts 将 @agri/* 别名直接解析到源码而非 dist，绕过构建顺序；Turbo 仅缓存 build/typecheck 任务，生产构建走 tsc -b。Node 版本锁定 >=24.0.0，所有子模块共享同一份 tsconfig 与依赖集。
