单文件 Node.js ESM 脚本，职责分层清晰：
- 进程编排：通过 `node:child_process.spawn` 拉起 `apps/control-service/dist/main.js` 与 `apps/iot-service/dist/main.js`，各自监听独立端口（CTRL=3651, IOT=3652），由 `waitHealth` 轮询 `/health` 就绪。
- 数据库层：使用 `pg.Client` 直连 PostgreSQL，提供 `waitRows` 通用轮询查询与 `cleanData` 清理 PLOT 相关数据。
- HTTP 客户端：封装 `request` 统一调用 control/iot 的 `/api/v1` REST 接口。
- 硬件模拟：`createFieldSlave` 基于 `node:net` 自建最小 Modbus TCP 从站，按 MBAP/PDU 手工编解码 FC05/FC02/FC03，复用 `getModbusProfile` 取点位定义但不复用平台侧编解码库，以暴露两端实现差异。
- 主流程：按编号①~⑧顺序覆盖接入目录校验、建档约束、缺省值补齐、灌溉/急停/故障等指令闭环、回调式设备隔离，最终断言回执落库与 `control_outbox` 事件主题一致。
依赖方向单向：脚本 → control/iot HTTP API + pg → 被测服务 → 假从站；不反向依赖被测服务的内部模块。
